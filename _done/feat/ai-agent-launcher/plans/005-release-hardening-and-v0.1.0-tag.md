# WP-005: Release hardening and v0.1.0 tag

Status: complete

## Outcome

Ship a tag-only `v0.1.0` release of `ai-agent-launcher` with no public legacy
migration interface. Replace the three existing local legacy launchers
manually before removal, preserving their existing session state without
recording local paths, configuration values, or session references in
repository artifacts.

## Implementation

- Back up the legacy configuration and three local launchers outside `PATH`.
  Recreate the TOML configuration manually from the recognized legacy settings.
  Recreate each launcher with `launcher create`, its existing worktree and
  local directories, marker `# generated by ai-agent-launcher`, and its
  worktree's `scripts/dx/setup-worktree-links.sh` preparation helper. Preserve
  each replacement's existing pinned or unpinned state privately.
- Delete the `migrate` CLI group, migration dispatch, `_migration.py`, and its
  tests. The released command must contain no Bash import or legacy launcher
  parser.
- Add an adapter-owned launcher-run operation that accepts generic context,
  optional session reference, settings, and pass-through arguments. The neutral
  lifecycle must not construct Codex-shaped option namespaces.
- Add fake-adapter contract coverage for generated-launcher execution and keep
  direct run, Codex session, fork, and worktree behavior unchanged.
- Add a release-only `make release-check` that runs normal validation, builds
  with `uv build --no-sources`, then verifies a clean temporary Git-tagged tool
  installation in isolated UV tool, binary, and cache directories.
- Add public installation and release guidance for source tags, forks, PATH,
  selected-tag upgrades, and the no-PyPI policy.

## Release and verification

- `make all` and `make release-check` pass.
- The local replacements retain worktree, session, preparation, and local
  writable-directory behavior; metadata comparisons report only pass/fail.
- Commit and push product changes, create and push annotated `v0.1.0`, then
  perform an isolated install smoke test against the public tag.
- Distribution metadata remains `mikebd-py-scripts`; `ai-agent-launcher`
  remains the public executable. No GitHub Release object, PyPI publication, or
  CI workflow is added.

## Completion evidence

- The three local legacy launchers were backed up outside `PATH`, manually
  recreated as generated launchers, and privately verified. Two retained their
  existing pinned session state; the remaining launcher retained its unpinned
  state.
- `make release-check` passes: Ruff, Pyright, 82 pytest tests, `uv build
  --no-sources`, and an isolated `uv tool install` smoke test from a temporary
  Git tag.
- The reviewed product is merged to `main`; annotated `v0.1.0` points to
  `f0291bf`, and an isolated public-tag installation reports version `0.1.0`
  with the `ai-agent-launcher` executable.

## Amendments

- 2026-08-23: A review finding identified setuptools metadata deprecation
  warnings during package builds. The release candidate now uses the SPDX
  license expression, explicitly includes `LICENSE`, requires the supporting
  setuptools version, and removes the deprecated license classifier. This
  preserves the release scope while making `make release-check` warning-free
  for those metadata notices.
- 2026-08-23: A review finding identified that only generated-launcher runtime
  delegation had a fake adapter contract test. The release candidate now also
  verifies generic `fork_session` and `find_session` delegation, resulting
  launcher metadata, and cross-worktree adoption rejection without Codex
  internals. This preserves the adapter boundary as future adapters are added.
- 2026-08-23: The public guide now documents both a fast untagged-checkout
  smoke test and an isolated local tool installation. The latter uses temporary
  UV directories so it neither requires a Git tag nor replaces the normal
  installed launcher.
